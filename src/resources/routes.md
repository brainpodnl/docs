# Routes

A Route makes an App accessible over HTTP and HTTPS. Without a Route, an App has no public HTTP endpoint, although it can expose [private TCP ports](apps.md#private-networking) to other Apps in the same pod.

Brainpod assigns every Route a unique `*.route.brainpod.io` hostname. The hostname is generated by the platform and cannot be selected or changed by the client.

## Configure routing rules

Every Route contains at least one rule. A rule selects:

- a name;
- a path prefix, such as `/` or `/api`;
- the target App;
- the target port;
- public or member-only access.

Use multiple rules to send different paths to different Apps. For example, send `/api` to an API App and `/` to a frontend App. Route target ports do not need to be declared as internal App ports.

When the console detects exposed ports in the selected image, it suggests them after you change the target App. Review the saved port before deploying.

## Protect a rule with Brainpod login

Under **Access**, choose one of:

- **Public**: anyone can access the rule without signing in to Brainpod.
- **Require Brainpod login**: only the pod owner and members can access the rule.

Access is configured per rule, so one Route can expose public application paths and protect an administration path. In a resource document, protected rules contain:

```json
{
  "auth": {
    "provider": "brainpod"
  }
}
```

Authentication applies before the request is forwarded to the App. The App still needs its own authorization when different signed-in pod members require different permissions.

## Add custom domains

Add custom domains from the Route editor or the pod's **Domains** page. Connect each domain with an external CNAME or with a [Brainpod-hosted DNS zone](dns-zones.md). Brainpod provisions TLS for generated and custom hostnames.

See [Custom domains](../custom_domains.md) for the complete domain workflow.

## Response caching

Brainpod-managed Route delivery does not store application responses in a shared CDN cache or coalesce requests around a cached response. Responses are forwarded from the application.

Configure cache headers for browsers and private caches in the App. Add a separate CDN only when the application's data model and cache keys make shared caching safe.

## Multiple Routes

Create separate Routes when applications need independent hostnames, domains, timeouts, or access rules. Multiple Routes can target the same App.

## Use the CLI

Inspect the Route schema and retrieve a Route from the current revision:

```sh
brainpod describe resource route --json
brainpod --pod my-pod resource get route web
```

Route mutations update the mutable head. Review the revision and run `brainpod deploy --wait` to make the configuration active.
